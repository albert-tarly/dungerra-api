# Database

The server persists users, game sessions and the leaderboard through a small storage layer in `internal/db` with two interchangeable backends.

| Backend | `DB_DRIVER` | Use it for | Notes |
|---------|-------------|------------|-------|
| SQLite (embedded) | `sqlite` | local development, single-server and desktop builds | One file, no external service. Pure-Go driver (`modernc.org/sqlite`), so no CGO; the server still cross-compiles to a single binary. |
| MongoDB | `mongodb` | hosted deployments, multiple server instances | Requires a MongoDB server (e.g. Atlas). |

## Configuration

```bash
DB_DRIVER=sqlite                 # "sqlite" or "mongodb"
SQLITE_PATH=data/dungerra.db     # sqlite only; directory is created if missing
MONGODB_URL=mongodb+srv://...    # mongodb only
```

If `DB_DRIVER` is not set, the server uses `mongodb` when `MONGODB_URL` is set and `sqlite` otherwise, so existing MongoDB deployments keep working without changes.

`SQLITE_PATH` is relative to the working directory. For a desktop bundle, point it at the OS application-data directory instead.

## Architecture

```
internal/db/
├── models.go   # User, GameSession, LeaderboardEntry, ... (shared by all backends)
├── store.go    # Repository interfaces, Open/Close, ErrNotFound / ErrDuplicate
├── mongo.go    # MongoDB backend
└── sqlite.go   # SQLite backend + schema migrations
```

Application code depends only on the interfaces:

```go
db.Open(db.Options{Driver: cfg.DBDriver, MongoDBURL: cfg.MongoDBURL, SQLitePath: cfg.SQLitePath})
defer db.Close()

users := db.NewUserRepository()         // db.UserRepository
sessions := db.NewGameSessionRepository() // db.GameSessionRepository
leaderboard := db.NewLeaderboardRepository() // db.LeaderboardRepository
```

Errors are backend-neutral: a missing record is `db.ErrNotFound` and a uniqueness violation is `db.ErrDuplicate`. Check them with `errors.Is`, never with driver-specific errors.

IDs are `primitive.ObjectID` values generated by the server (stored as hex strings in SQLite), so they look the same on both backends.

## SQLite details

- **Schema:** relational columns for everything that is filtered or sorted on (with the same indexes as MongoDB). A session's `players`, `world_map` and `shared_objects` are stored as JSON, and so is its `difficulty` (an empty string for sessions created before difficulties existed, which play as Hard).
- **Migrations:** `sqliteMigrations` in `sqlite.go`; the applied count is recorded in `PRAGMA user_version`. Only append new migrations; never edit one that has shipped.
- **Concurrency:** WAL journal mode, a 5 s busy timeout and a single connection. This is plenty for the server's write pattern (periodic session saves, leaderboard updates on death), but it means one SQLite file serves **one server process**. Use MongoDB to run several instances.
- **Backups:** copy the database file while the server is stopped, or use `sqlite3 data/dungerra.db ".backup backup.db"` while it runs.

Numbers in JSON-stored world objects decode as `float64` (BSON yields `int32`/`int64`). Code that reads `WorldObject.Properties` must accept both, as `toInt64` / `asStringMap` in `internal/game/session.go` do.

## MongoDB details

- Database name: `dungeon_game`; collections `users`, `game_sessions`, `leaderboard`.
- Indexes are created on startup (failures are logged as warnings).
- **User migration** (runs on every start, idempotent): legacy users get `provider: "google"` and `provider_id = google_id`, and the legacy unique `email_1` index is dropped. If it fails, the server does not start, because logins would break otherwise.

## Tests

`internal/db/store_test.go` is a contract test that every backend must pass. SQLite always runs; to include MongoDB, point `MONGODB_TEST_URL` at a **disposable** instance (the tests write to the real `dungeon_game` database name):

```bash
go test ./internal/db
MONGODB_TEST_URL=mongodb://localhost:27017 go test ./internal/db
```

## Adding a backend

Implement `db.Store` (and the three repository interfaces), add a driver constant and a case in `db.Open`, and add it to `backends()` in `store_test.go`.
